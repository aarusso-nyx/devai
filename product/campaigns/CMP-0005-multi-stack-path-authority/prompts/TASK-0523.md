## Deliverables

- buildTrustedAuthoritySources reads the binding receipt, loads and validates the source it names, merges the default test selectors from the law source (registered in packages/schemas/src/roster.ts) when the block omits them, and appends the compiled document as the second additive extension after devai-adopter-authority, so init bind, the broker, the session, and Doctor all derive the same digests; a receipt whose source is missing or invalid raises ADOPTER_AUTHORITY_SOURCE_UNAVAILABLE and a source without the block yields exactly one extension, byte-identical to today.
- init bind --adopter-policy writes the authority_extension provenance (extension_id, extension_version, digest_sha256, rule_count) into the receipt and parseAdopterPolicyBinding admits it as optional; the resolver denies AMBIGUOUS_POLICY_MATCH when the highest matched precedence holds additive-extension rules with different human role sets and leaves core unions unchanged; docs/reference/error-codes.md lists the new codes.
