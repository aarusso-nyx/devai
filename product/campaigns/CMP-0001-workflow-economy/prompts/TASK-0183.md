# TASK-0183 Schema-driven prompts and the interactive init plan flow

Role: Engineer. Round R-0106, wave CTG-0108. Record: ADR-CFG-0001.
Tier: worker-high (resolve the host model from `models.tiers` in campaign.json). Effort: high. Time budget: 120 minutes.
Upstream: TASK-0181 and TASK-0182 have landed. Make the tests green.

## Steps

1. `packages/cli/src/services/schema-prompts.ts`: map a JSON schema object to a
   prompt sequence on `node:readline/promises`: enumerations become numbered
   selections, patterns become validated text, descriptions become help. No new
   dependency; `pnpm run release:closure` must stay green.
2. `packages/cli/src/services/interactive-config.ts`: the two modes. Bind mode
   collects tier, project type, repo kind, docs builder, includes, and tracking
   opt-in, builds the plan through `buildBootstrapPlan`, shows the diff, asks for
   role and write consent, and invokes the existing `init bind` and `init apply`
   handlers. Edit mode lists adopter-owned keys, refuses materialized files with a
   re-bind offer, and writes through the same handlers. Both end by printing the
   equivalent argv.
3. `packages/cli/src/commands/init/index.ts`: add `--interactive` to `init plan`;
   with no terminal on standard input, emit a structured error and perform no
   write.
4. Regenerate `docs/reference/cli/index.md` with
   `node docs/reference/cli/render-generated-reference.mjs --write`.
