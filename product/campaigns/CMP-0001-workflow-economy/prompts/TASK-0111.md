# TASK-0111 Toolchain manifest schema, manifest, and default

Role: Architect. Round R-0101, wave CTG-0101. Record: ADR-CHK-0002.

## Steps

1. Create `law/schemas/toolchain-manifest.schema.json` (draft 2020-12, meta gate:
   `$id` under `https://devai.nyxk.com.br/schemas/`, title, description,
   `schema_version`, at least one example, `additionalProperties: false` on
   every object). Declare: `runtimes` (node, pnpm, git; exact version strings),
   `actions` (map from action repository to `{ref, digest, peeled_commit?}`
   covering every constant exported at the top of `scripts/check-workflows.mjs`),
   `verifier` (package name and version referencing
   `law/policy/trusted-local-rc-verifier-package.json`, never a copy of it),
   and `constants` (named repository constants such as `expected_action_count`).
2. Create `.devai/config/toolchain.json` with the live values. Read them from
   `.github/workflows/*.yml`, `scripts/check-workflows.mjs`,
   `scripts/release-host/provision-toolchain.mjs`, and the `packageManager` field
   of `package.json`. If two sources disagree, stop and report which.
3. Create `law/policy/adopter-defaults/toolchain.json` with the same shape.
4. Add both file names to `SOURCE_ONLY_SCHEMAS` in
   `packages/cli/src/commands/check/schemas.ts` so the schema catalogue stays
   complete. That is the only code line you touch.
5. The manifest is adopter-owned, so do not add it to
   `scripts/check-policy-materialization.mjs`; state that decision in your report.
6. Add a "Toolchain manifest" section to `docs/adopters/test-tasks.md`.

## Acceptance

```bash
node scripts/check-policy-materialization.mjs
node .devai/state/pr-bootstrap/cli/bin.js check --only schemas --format json
```
