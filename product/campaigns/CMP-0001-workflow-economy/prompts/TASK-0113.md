# TASK-0113 Consume the toolchain manifest

Role: Engineer. Round R-0101, wave CTG-0101. Record: ADR-CHK-0002.
Tier: worker-high (resolve the host model from `models.tiers` in campaign.json). Effort: high. Time budget: 120 minutes.
Upstream: TASK-0111 (schema, manifest) and TASK-0112 (tests) have landed. Make
the tests green without weakening them.

## Steps

1. `scripts/check-workflows.mjs`: load `.devai/config/toolchain.json` at check
   time and derive the exported pin constants from it, keeping the export names.
   For every action reference and node version in every workflow, emit a finding
   with file, manifest key, observed, and required when they differ. Verify
   `EXPECTED_ACTION_COUNT` in `release.yml` against `constants.expected_action_count`.
2. `scripts/release-host/provision-toolchain.mjs`: remove the inline versions
   the manifest owns and read them from the manifest path named in the controls
   file. Fail with `DEVAI_TOOLCHAIN_MANIFEST_REQUIRED` when absent. Keep the
   Debian package table if the manifest does not model it and say so.
3. `packages/cli/src/services/check-runner/runner.ts` and `policy.ts`: derive the
   toolchain digest from the canonical manifest bytes plus the executable identities
   the runner already records. Find the current derivation with
   `graft grep "resolvedRunnerToolchain"`.
4. Workflows (`.github/workflows/pull-request-checks.yml`, `release.yml`,
   `devai-ledger-verify.yml`): GitHub Actions cannot read a JSON file for a `uses:`
   digest, so keep the literals and rely on the checker. For step environment values (node
   version, `EXPECTED_ACTION_COUNT`) keep the literal and add a comment naming
   the manifest key the checker verifies.
5. Update the two script rows in `docs/reference/scripts.md`.
