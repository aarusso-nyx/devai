## Deliverables

- .github/workflows/update-pull-request-branches.yml runs on push to main and, for every open non-draft pull request against main that is behind it, calls PUT /repos/{owner}/{repo}/pulls/{number}/update-branch with update_method rebase and the expected head sha. It skips a pull request whose rebase conflicts and reports it without failing the others. It uses a GitHub App or other non-GITHUB_TOKEN credential, because a push made with GITHUB_TOKEN starts no workflow run and the rebased head would never be gated. The workflow holds the least permissions it needs.
- The superseded gate run is cancelled rather than failed. The existing concurrency group of pull-request-checks.yml, keyed by workflow and pull request number with cancel-in-progress, already cancels an in-progress run when the rebased head arrives as a synchronize event; the task verifies this on a live pull request, records the run ids in its pull request, and changes the gate workflow only if the verification fails.
- scripts/check-workflows.mjs pins the trigger, the rebase update method, the credential source, and the concurrency group, so removing any of them fails the workflow check.
