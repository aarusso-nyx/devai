# TASK-0267 Declare the unit, integration, and e2e suite invocations as sensor inputs

Role: Engineer. Round R-0206, wave CTG-0267. Record: ADR-SCR-0005.
Tier: worker-high (resolve the host model from `models.tiers` in campaign.json). Effort: high. Time budget: 90 minutes.

## Steps

1. Read `packages/sensors/src/test.ts`: `senseTest` hardcodes
   `tests/config/t1.unit.config.ts`, `t3.integration.config.ts`, and `t5.e2e.config.ts`,
   none of which exist in this repository, so `unit_test`, `integration_test`, and
   `e2e_test` read error on the framework and F3:T1 reads FAIL. Read how TASK-0264
   declared `perf_test.argv` in `law/schemas/sensor-inputs.schema.json`,
   `.devai/config/sensor-inputs.json`, `packages/sensors/src/perf-test.ts`, and
   `packages/cli/src/commands/sense/adapters.ts`, and the governed vitest shape the
   broker admits in `packages/cli/src/authority/broker.ts` (`tests/config/local.config.ts`
   or `rc.performance.config.ts` plus one path under `tests/`).
2. Add `unit_test.argv`, `integration_test.argv`, and `e2e_test.argv` inputs to the
   schema with the same shape as `perf_test.argv`; declare for DEVAI
   `["pnpm","vitest","run","--config","tests/config/local.config.ts","tests/contract"]`,
   the same with `tests/integration`, and the same with `tests/e2e`. Keep the hardcoded
   suite configurations as the fallback when no argv is declared.
3. Thread the declared argv through `senseTest` and the three adapters; pin the declared
   values in `packages/sensors/tests/declared-inputs.test.ts`,
   `packages/cli/tests/unit/sense-inputs-declaration.test.ts`, and
   `tests/contract/sensor-inputs.contract.test.ts`; refresh
   `packages/cli/tests/unit/doctor-check-result-identities.test.ts` if the schema
   digest changes. Document the inputs in `docs/adopters/sensor-inputs.md`.
4. Run the three sensors on the repository under `sense run`; each must report pass
   with the declared argv as its command.
