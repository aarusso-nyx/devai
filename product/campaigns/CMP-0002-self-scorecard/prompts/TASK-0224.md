# TASK-0224 Admit gh run list as a read-only host process for the harness sensors

Role: Engineer. Round R-0202, wave CTG-0222. Record: ADR-SCR-0005.
Tier: worker-high (resolve the host model from `models.tiers` in campaign.json). Effort: high. Time budget: 90 minutes.

## Steps

1. Read ADR-SCR-0005 and the preflight probe admission from ADR-CHK-0001 in
   `packages/cli/src/services/check-runner/authority-process.ts`.
2. Declare the read-only process in `law/policy/authority-policy.json` and mirror it in
   `.devai/config/authority-policy.json` in the same commit.
3. In `packages/cli/src/authority/broker.ts` extend `readOnlyProcess` to accept the
   declared shape; refuse any other gh argv.
4. Confirm the three harness sensors in `packages/sensors/src/` need no change beyond
   the argv they already emit; adjust only if their argv differs from the declared
   shape.
5. Write `packages/cli/tests/unit/authority-host-process-read-only.test.ts`.

## Deliverables

- The authority policy declares gh run list, with a fixed argv shape and --json, as a
  read-only process the broker admits without a host adapter, the same way preflight
  probes were admitted.
- harness_green_main, harness_performance, and harness_robustness produce readings
  instead of AUTHORITY_HOST_PROCESS_ADAPTER_REQUIRED.
- A test proves that gh with any mutating subcommand is still refused.
