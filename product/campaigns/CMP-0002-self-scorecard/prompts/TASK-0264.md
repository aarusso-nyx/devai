# TASK-0264 Declare the performance suite invocation as a sensor input and run it under the broker

Role: Engineer. Round R-0206, wave CTG-0264. Records: ADR-SCR-0005, ADR-SCR-0003.
Tier: worker-high (resolve the host model from `models.tiers` in campaign.json). Effort: high. Time budget: 90 minutes.

## Steps

1. Read `packages/sensors/src/perf-test.ts`, `law/schemas/sensor-inputs.schema.json`,
   `.devai/config/sensor-inputs.json`, and the `readOnlyGhProcess` and vitest admissions
   in `packages/cli/src/authority/broker.ts`. The `test:perf` script exists after
   TASK-0263, but the sensor still shells out through the package runner, which the
   broker does not admit, so perf_test cannot report pass under `sense run`.
2. Add a `perf_test.argv` input to the schema and declare DEVAI's argv as the vitest
   invocation of `tests/config/rc.performance.config.ts` over `tests/regression`; keep
   `scriptName` as the legacy key. Run the declared argv without a shell in
   `packages/sensors/src/perf-test.ts`, and thread it through
   `packages/cli/src/commands/sense/adapters.ts`.
3. Admit the governed vitest configurations that exist in the checkout as a read
   template in `law/policy/subprocess-effects.json` (mirror
   `.devai/config/subprocess-effects.json`) and in the broker allowlist. Declare DEVAI's
   `type_check.argv` as a broker-admitted shape.
4. Align the host test scope in `packages/skills/tests/unit/authority-host-test-scope.ts`
   and refresh the frozen doctor digest in
   `packages/cli/tests/unit/doctor-check-result-identities.test.ts`; pin the declared
   argv values in `packages/sensors/tests/declared-inputs.test.ts`,
   `packages/cli/tests/unit/sense-inputs-declaration.test.ts`,
   `packages/cli/tests/unit/sense-adapter-acceptance.test.ts`,
   `packages/cli/tests/unit/authority-broker-readonly-process.test.ts`,
   `packages/cli/tests/unit/cli-shard09-sense-run-set-command.test.ts`, and
   `packages/cli/tests/unit/cli-shard09-sense-run-set-execution.test.ts`.
5. Document the new input and the legacy key in `docs/adopters/sensor-inputs.md`.
