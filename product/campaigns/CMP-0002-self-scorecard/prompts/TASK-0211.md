# TASK-0211 Admit sense run, sense record, and audit observe in the self-dogfood policy

Role: Architect. Round R-0201, wave CTG-0211. Record: ADR-SCR-0001.
Tier: architect (resolve the host model from `models.tiers` in campaign.json). Effort: high. Time budget: 120 minutes.

## Steps

1. Read ADR-SCR-0001 and ADR-GOV-0002. The amendment adds actions to the matrix; it
   never widens a role or admits a remote effect.
2. Edit `law/policy/self-dogfood.json`: add `sense run` (effect read) to every row's
   `may_initiate`; add `sense record` and `audit observe` (effect harness-write) to the
   inspector row only; add the three action ids to `permitted_checks` with their
   initiator roles.
3. Edit `law/schemas/self-dogfood-policy.schema.json` so the harness-write actions are
   structurally limited to rows that permit harness-write, and keep the structural
   remote-write prohibition intact.
4. Edit `packages/cli/src/services/self-dogfood.ts` so the decision for `sense run`,
   `sense record`, and `audit observe` is taken from the matrix rather than allowed by
   omission, and so `--publish` on any sense action is refused before the matrix is
   consulted.
5. Write `packages/cli/tests/unit/self-dogfood-policy.test.ts` with one case per
   inspector acceptance item of ADR-SCR-0001.
6. Record the admission in the campaign guide `docs/dev/operations/self-scorecard-
campaign/README.md` under "Self-dogfood limits".

## Deliverables

- The policy names sense run with effect read for every role, sense record and audit
  observe with effect harness-write for the inspector only, and keeps remote-write
  forbidden in every row.
- The schema rejects a row that admits sense record or audit observe with any effect
  other than harness-write.
- The self-dogfood service refuses sense run --write from every role except the
  inspector and refuses any sense action that names --publish.
- Unit tests cover admission, refusal, and the fail-closed remainder for the three
  actions.
