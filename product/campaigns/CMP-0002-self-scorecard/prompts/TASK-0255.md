# TASK-0255 Declare the reusable-workflow threshold of the harness idiomaticity sensor as a sensor input

Role: Engineer. Round R-0205, wave CTG-0255. Record: ADR-SCR-0005.
Tier: worker (resolve the host model from `models.tiers` in campaign.json). Effort: medium. Time budget: 60 minutes.

## Steps

1. Read ADR-SCR-0005 and TASK-0254's report: harness_idiomaticity scores a reusable
   workflow whenever the repository has at least one workflow, because
   `minWorkflowsForReusableCheck` defaults to 1 in
   `packages/cli/src/commands/sense/adapters.ts` with no override. A three-workflow CLI
   repository sharing setup through a composite action has no job set to reuse.
2. Add `minWorkflowsForReusableCheck` (integer, minimum 1) under
   `inputs.harness_idiomaticity` in `law/schemas/sensor-inputs.schema.json`; declare 5
   in `.devai/config/sensor-inputs.json`; leave `law/policy/adopter-defaults/sensor-
inputs.json` undeclared. Split schema and declarations into separate commits if the
   commit-range checker keeps spec and generated apart.
3. In `packages/cli/src/commands/sense/shared.ts` expose the key and in `adapters.ts`
   pass it to `packages/sensors/src/harness-idiomaticity.ts` instead of the hardcoded
   default; undeclared keeps today's behavior.
4. Extend `packages/sensors/tests/declared-inputs.test.ts`,
   `packages/cli/tests/unit/sense-inputs-declaration.test.ts`, and
   `tests/contract/sensor-inputs.contract.test.ts`; document the key in
   `docs/adopters/sensor-inputs.md`.
