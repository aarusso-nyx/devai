# Current offline mutation evidence

## Status

Proposed forward correction for the unreleased 1.5 candidate. Control approval
and release authority remain separate.

## Context

The offline receipt's ninth row requires an MA2 report for its historical
non-applicable/pass distinction. Current portable mutation evidence uses verified
release-unit closures; the retired MA2 writer cannot produce that evidence.
Inventing an MA2 identifier would not implement independent verification.

## Decision

Add the explicitly discriminated `devai.release-unit-mutation-check.v1` row to
the pre-release 2.1 receipt grammar. Keep all historical rows readable and keep
1.0/2.0 restricted to their historical grammar. No existing signed receipt bytes
are rewritten. The new row records every unit's exact version, verified plan
receipt digest, required/none determination and, when required, verified portable
mutation closure. Its digest also binds repository and candidate identity.

Only a completed, invocation-scoped policy, artifact and portable mutation
verification may supply this row. An all-none row is not-applicable only when
every replayed plan explicitly says none/not-required. A passing row must have
at least one required unit with its complete verified closure. Missing units,
substituted plan digests, reordered populations, unavailable required evidence
or changed closures refuse; they cannot become not-applicable. The returned row
is compared again against verified inputs before accepting the offline receipt.

## Consequences

This changes no mutation threshold, survivor limit, task population, public
CLI action, signer authority or remote effect. The concrete offline provider
emits the current discriminated row; legacy MA2 grammar is for historical
compatibility, not an alternate way to certify current unit mutation evidence.

The separately reviewed control correction required by ADR-REL-0025 provides
DAG/census verification without generated bytes. That result alone does not
verify signatures, actual exported artifact bytes/safety or mutation semantics.
Control approval remains separate from candidate implementation and this ADR.

## Alternatives Considered

Synthesizing an MA2 report is rejected because it would not bind current unit
semantics. Removing legacy grammar is rejected because retained historical
receipts must remain readable. Replacing mutation verification with schema
validation is rejected because valid JSON does not prove execution or limits.

## Affected Rules

Only the current offline receipt schema and its verification implementation
change. The mutation policy and its approved verifier provenance remain intact.

## Inspector Adversarial Acceptance

Exercise all-required, all-none and mixed unit populations. Reject missing,
extra, duplicate or substituted units; required evidence without a closure;
changed plan digests; changed candidate identity; fabricated or expired
verification contexts; and legacy receipts carrying the new row. Preserve old
receipt examples and the complete schema/test census.
