# Bind portable certified evidence to the aggregate export signature

## Status

Proposed narrow forward compatibility decision. It corrects the demonstrated
absence of certification task evidence from the portable export closure. It
does not add an action, artifact kind, signer, authorization, tag, review
mechanism, remote effect, or mutation execution.

## Context

ADR-REL-0022's v3 export binds policy closure, prepared package artifacts, and
portable mutation evidence. It does not retain the original candidate receipt,
task-policy bytes, every task-result byte, or an authenticated realised
generated-namespace census. Those bytes are required to establish the mandatory
offline `result-dag-integrity` check after the protected certification cache and
checkout are absent. Treating their digests as interchangeable with their bytes
would turn an incomplete representation into a false passing check.

The correction must retain the existing five artifact kinds and one aggregate
signer. It must not capture raw stdout/stderr or generated output bytes: neither
is required by the canonical verifier and either can expand the portable bundle
with sensitive or host-specific material.

## Decision

The current forward export contract is closure v4, transcript v3, and
provider-result v3. It retains exactly the existing five-kind, three prepared
parent plus two extension artifacts per package, and the existing `2N + 34`
operation accounting. No new sink member, signer operation, action, state,
authorization, tag, or remote effect is introduced.

Before `store.begin`, the protected export composition resolves one complete,
canonical certification evidence carrier for every resolved release unit,
including units whose mutation outcome is `none`. Each carrier contains the
unchanged canonical candidate receipt bytes, task-policy bytes, every canonical
task-result byte required by that receipt, and one digest-only namespace census.
The carrier is stored only in that unit's elected existing `provider-result`.
Missing, null, duplicate, substituted, extra, partial, or cross-unit carriers
refuse. Carrier byte-size and member-count limits are externally protected,
measured for the exact invocation, and fully preallocated before `store.begin`;
this decision supplies no unmeasured numeric default.

The one aggregate signature covers a canonical transcript that fully enumerates
the byte identities of the policy, candidate receipt, every result, census, and
the census's protected derivation binding for every unit. The transcript also
continues to bind parent identities, package-to-unit mapping, candidate, plan,
destination, trust, attempt, and all existing v3 projections. Provider results
remain post-signature members and final-manifest identities remain outside the
preimage, preserving the acyclic one-signature ordering.

The offline reader is pure: it may use only the exported bounded carrier bytes,
existing retained artifacts, signed transcript, and external expected identity
and trust inputs. It never obtains authority from a checkout, cache, network,
host path, or ambient installed source. It validates the original task policy,
candidate receipt and task results rather than reconstructing a passing result.
The namespace census is a canonical, signed digest-only document containing
only producer task, protected derivation binding, and path/mode/sha256/size
identities. It contains neither generated bytes nor raw stdout/stderr. The
canonical verifier extends the expected output population from that census only
after proving disjointness, node/prefix containment and equality with the
result-digest population.

For release task policies, `inputProjection` is legal only in schema version
`1.2.0`; it is emitted with that version exactly. Historical 1.0 and 1.1
validation remains strict and byte-compatible, and 1.1 plus `inputProjection`
continues to fail. A v4 export additionally requires the existing aggregate
verification's Ed25519/64-byte identity. Any non-Ed25519 identity refuses with
`SIGNATURE_ALGORITHM_UNSUPPORTED` before `store.begin` or signer dispatch.
Other algorithms remain governed only by legacy branches and cannot make a v4
offline-certification claim.

Offline verification emits all nine mandatory evidence checks with distinct,
nonzero evidence projections. It neither synthesizes check rows nor treats the
mandatory DAG check as not-applicable. v2 and v3 closure branches remain
read-only under their exact legacy interpretation, but lack of the complete
carrier makes them fail the mandatory DAG check rather than qualifying as a
current offline verification.

## Consequences

Engineer work first adds source-first canonical verifier support for task-policy
1.2 and the bounded carrier/census verifier API, then vendors the exact approved
source pin into DEVAI. The export producer retains the complete certification
population while it is authentic, validates capacity before side effects, and
binds its identity projection before the single signer invocation. No existing
policy/result bytes may be rewritten to fit the new format.

Inspector work proves complete and interrupted retention, absent/extra/tampered
receipt, policy, task-result and census populations, namespace derivation and
census drift, missing source/cache, non-Ed25519 pre-begin refusal, legacy DAG
failure, and nine distinct nonzero receipt evidence projections.

## Alternatives Considered

**Use reported digests without retaining bytes.** Rejected: digests cannot
validate the candidate receipt or task DAG after the original source is absent.

**Add a sixth artifact kind or second signature.** Rejected: it expands the
release surface and operation accounting despite the elected provider-result
already being a signed carrier location.

**Retain generated bytes or raw streams.** Rejected: canonical DAG validation
requires their identities, not their bytes; retaining them creates unnecessary
privacy and portability exposure.

## Affected Rules

The lifecycle policy advances only the current export extension to v4 and its
schema permits that exact forward branch. v2 and v3 remain byte-identical
read-only branches. Public action, state, receipt, authorization, signer and
artifact-kind contracts remain unchanged.

## Inspector Adversarial Acceptance

Verify a complete all-required and all-none unit population offline from a
different checkout with the certification cache absent. Refuse every missing,
duplicate, extra, cross-unit or digest-mismatched carrier member; every altered
policy, receipt, result, census or derivation binding; a malformed 1.1 policy
with `inputProjection`; any non-Ed25519 v4 route before side effect; ambient
lookup; and any receipt that reuses, zeroes, duplicates, synthesizes, or marks
the DAG evidence row not-applicable.
