# B1 Owner host custody: exact proposed boundary

Status: proposed Architect checkpoint; no issuer, key or reconciliation writer has been implemented by this document. This supplements owner-intake-decision.md and the 50+18 candidate inventory. DETRAN execution remains excluded.

## Bound host targets

Resolve the real repository and its actual worktree Git administration directory using the trusted existing Git resolver, ignoring caller Git environment overrides. Linked worktrees use their own administration directory, never the shared common directory. Bind the attestation to both real repository/worktree identity and administration-directory device/inode identity. Reject symlinked target components, foreign ownership, group/world accessible secret/state roots and unsupported administration layouts before mutation. The following are logical paths; callers cannot pass physical equivalents or alternate roots.

| Logical target                   | Exact physical resolution and standing                                                                                                                         |
| -------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| reconciliation-host/provisioning | `<worktree-gitdir>/devai/reconciliation/provisioning.json` (mode0600, immutable signed provisioning intent)                                                    |
| reconciliation-host/key          | `<worktree-gitdir>/devai/reconciliation/key` (32 random bytes, mode0600, create only)                                                                          |
| reconciliation-host/attestation  | `<worktree-gitdir>/devai/reconciliation/attestation.json` (mode0600, create only, HMAC by separate key)                                                        |
| reconciliation-host/approval/ID  | `<worktree-gitdir>/devai/reconciliation/approvals/<ID>/approval.json` (mode0600, immutable HMAC document)                                                      |
| reconciliation-host/phase/ID/N   | `<worktree-gitdir>/devai/reconciliation/approvals/<ID>/phase-<N>.json` (N exactly01,02,03,04; immutable HMAC completion event)                                 |
| reconciliation-host/intent/ID/N  | `<worktree-gitdir>/devai/reconciliation/approvals/<ID>/intent-<N>.json` (immutable HMAC pre-effect intent, exact expected-before and expected-after witnesses) |
| reconciliation-host/lease/ID     | `<worktree-gitdir>/devai/reconciliation/approvals/<ID>/lease` (exclusive owned publication, operation/phase/nonce/PID and expected predecessor event digest)   |

ID is a host-generated 64 lowercase hexadecimal random identifier, not an output path or caller-selected arbitrary string. All physical roots and parent identities are retained/rechecked by the typed host adapter. No tracked declaration/config, Git hook, executable issuer script, generic `.git` permission or post-merge key change is needed. Trust entry is a registered installed operation plus its host attestation, not a caller-written declaration. The installed implementation/module digests are bound instead of installing a second executable.

Provision only through exact `devai init bind --reconciliation-host --target <repo> --as-role owner --write --format json`, all three streams real TTY; no session/machine identity, other selector, argument aliases, equals forms, key/output/receipt/admin path option or extension. Without --write, the exact selector may emit a read-only bounded plan and must not create directories. Direct Owner consent, current ordinary bound authority, canonical installed package identity and actual target paths are required before first mkdir/key publication. This is a distinct init selector, not a modifier of P1 policy review. No authority-policy or project mutation is part of provisioning.

Provision order: verify all absence/identities and freeze plan; display exact targets/effects and digest; case-exact `BIND RECONCILIATION-HOST <plan_sha256>`; fresh actual checks; create private directories, publish key create-only, publish attestation create-only. Ordinary repeat verifies complete matching binding and returns original attestation. Existing malformed/foreign/stale files refuse. Crash after key-only returns `RECONCILIATION_HOST_INCOMPLETE`; direct Owner retry may complete only an exact owned provisioning intent retained in `<root>/provisioning.json`, including package/binding/plan/key digest. Publish this intent before key; key-only without valid matching intent stays held. No rotation, revocation, repair overwrite or stale-key deletion in this scope. Completed provisioning retains the intent as evidence. An expired approval is replaced only by a new approval ID, never by changing a receipt.

## Closed signed documents

Use one explicitly versioned deterministic canonical JSON byte encoding across producer/verifier. HMAC-SHA256 domain separators distinguish provisioning, attestation, approval, phase-intent and phase-completion; timing-safe signature comparison. Every schema has additionalProperties:false. Validate schema before verification/use, enforce file size limits and do not return key bytes through reports.

Attestation binds schema_version, adapter_id/kind, repository realpath and directory identity, worktree gitdir realpath/identity, key_sha256, installed package name/version/module+registry identity, installed Constitution digest, actual authority-policy digest, provision plan digest and installed_at_head. Each invocation recomputes these actual bindings; a policy/package change refuses rather than silently reattesting. Provisioning intent additionally binds exact key/attestation target identity and expected absence; it is signed by the freshly generated key before its public create-only publication.

Approval binds ID, issuer/attestation digest, issued_at/expires_at (maximum15minutes), repository/worktree bindings, original HEAD/base/all merge parents, original semantic index witness, exact source-manifest bytes/digest, exact complete plan bytes/digest, custody destinations/hashes, selected published parent and complete immutable prefix digest, closed intended phase outputs/effects, Constitution/policy/package identity. No boolean approved or caller key has authority. Approval is emitted only by direct Owner action after exact READY and case-sensitive `APPROVE RECONCILIATION <plan_sha256> <source_manifest_sha256>` within300000ms monotonic time. Recheck frozen actual state and current ordinary Owner authority after confirmation. EOF, expiry, wrong token, drift or missing TTY emits refusal/cancel without key/state/chain/index/diagnostic mutation.

Approval expiry blocks starting any new phase. A signed already-started phase intent may only be settled by verifying its exact resulting state; it cannot authorize a different operation or new phase after expiry. Terminal expiry does not roll back complete output. A caller supplies only approval ID to later registered actions; adapter derives every path and verifies actual authority separately. No report replay API.

## Phase consumption and crash handling

Acquire exact owned lease via existing guarded create-only primitive; never take over based on elapsed time or PID absence. Verify approval, all predecessor completion documents, actual before-state and exact action/phase correspondence while holding lease, then publish signed immutable intent before any authorized domain output. The intent is not completion. Fresh ordinary authority is required for each domain mutation. After output readback validates exact bytes/identity and durable publication status, publish signed completion linked to intent, preceding phase digest and output witnesses. Release only exact owned lease inode using guarded identity removal. Surface indeterminate publication with owner identity and staged-presence fields, preserve whole linked targets and never claim successful completion on unknown durability.

1. phase01 `CUSTODY_DURABLE`: exact original stage1/2/3 proof-chain blobs and source manifest published create-only to fixed plan-derived record custody paths. No canonical selection/index write.
2. phase02 `CANONICAL_SELECTED`: complete selected published-parent prefix copied byte-for-byte plus a distinct reconciliation-selection event. Never synthesize/fold/drop original records. Final record projection and event schema require Architect closure; U1 recovered_from is not a selection record.
3. phase03 `PROOF_INDEX_PUBLISHED`: only after every exact U1/newest serial expected-head recovery from the plan has completed and been verified, publish semantic proof entry CAS to final recovered chain blob. Intent binds exact expected semantic index plus replacement blob/mode; preserve all unrelated entries and extensions. Existing real index.lock governs transaction. No alternate-index bypass.
4. phase04 `BOOTSTRAP_COMPLETE`: diagnostic-only native seven bodies from immutable staged source + shared snapshot overlay; source_kind staged-merge-bootstrap, real HEAD/MERGE_HEAD/index witnesses; no native-clean/readiness claim. Exact plan output paths only; catalogue conflict remains excluded from sensor input.

Recovery operations between02/03 have ordinary U1 role/consent/append lock and exact source+head checks; approval does not broaden U1. Phase03 independently verifies their complete exact resulting chain and plan membership; it cannot accept an arbitrary current chain merely because head is valid.

Exact retry after complete phase returns original verified completion. After intent but no output, same phase can resume only with current ordinary authority and unchanged before-state. After complete output but no completion, verify full intended output and settle same intent without duplicating output. Partial or foreign/mismatched output, changed inputs, indeterminate durability or an orphaned owned lease remain held; no automatic cleanup, takeover, new grant or rollback deletion. The first implementation may fail closed for an orphaned lease; an additional explicit recovery operation would require its own bounded contract rather than silently expanding these five actions. This is a deliberate availability limit, not an automatic stale-lock recovery promise.
