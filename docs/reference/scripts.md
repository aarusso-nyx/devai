# Repository scripts

The current root maintenance scripts are:

| Script                                         | Purpose                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| ---------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `scripts/check-campaign.mjs`                   | validate campaign plans under `product/campaigns`                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `scripts/check-change-hygiene.mjs`             | pre-commit and commit-msg hygiene: lint-staged, whitespace, single-family staged paths, and the commit grammar (`--commit-msg <file>`)                                                                                                                                                                                                                                                                                                                                                                                       |
| `scripts/check-commit-range.mjs`               | re-apply the commit grammar and single-family rule to first-parent commits in `<base> <head>`; run by the pull-request gate                                                                                                                                                                                                                                                                                                                                                                                                  |
| `scripts/check-workflows.mjs`                  | validate the current receipt-verification workflow shape, including the three-step pull-request lane (install, `check --preflight --run`, `check --affected --run` with the release gate), check every action digest, node version, and restated constant against `.devai/config/toolchain.json`, and require a bijection between each job's `secrets.NAME` and `github.token` references and the workflow consumers in `law/policy/credential-requirements.json` (`CI_CREDENTIAL_UNDECLARED`, `CI_CREDENTIAL_UNREFERENCED`) |
| `scripts/check-release-static-integrity.mjs`   | backs `release:static-integrity`: requires a clean tree, scans tracked package sources, `law/policy`, `law/schemas`, and committed configuration (`config/`, `.devai/config/`, `.github/`, root JSON and YAML) for private keys and GitHub or AWS token shapes (`RELEASE_SECRET_SURFACE_DETECTED:<path>`), and checks path portability                                                                                                                                                                                       |
| `scripts/process/release-prerequisites.mjs`    | local release prerequisites, certification, and evidence export; its `credentials <workflow> <job>` phase is the first step of both ledger verification jobs and fails with `CREDENTIAL_ABSENT:<id>` when a blocking manifest secret is absent, reading presence flags only                                                                                                                                                                                                                                                  |
| `scripts/run-pr-release-gate.mjs`              | pull-request release gate for `<base>`: commit range, bump floor, change-class release intent, and the profile-selected preflight; its affected run reuses the cache the lane's `check --affected --run` step fills                                                                                                                                                                                                                                                                                                          |
| `scripts/pr-failure-diagnostics.mjs`           | print the bounded, redacted failure tails of every non-PASS node the lane ran, and the remediation of every BLOCKED preflight probe node                                                                                                                                                                                                                                                                                                                                                                                     |
| `scripts/release-host/provision-toolchain.mjs` | build the protected release-host toolchain image; reads runtime versions from the manifest named by `manifest_path` in its controls file and refuses with `DEVAI_TOOLCHAIN_MANIFEST_REQUIRED` without it                                                                                                                                                                                                                                                                                                                     |
| `scripts/release-channel.mjs`                  | derive the release channel (`alpha`, `beta`, `rc`, or `stable`) and its dist-tag (`alpha`, `beta`, `next`, or `latest`) for `<version>` from the prerelease ladder in `law/policy/release-lifecycle.json`; refuses a prerelease identifier outside the ladder with `RELEASE_VERSION_INVALID:<version>`                                                                                                                                                                                                                       |
| `scripts/create-release-manifest.mjs`          | write the release manifest for the exact package version, recording its release type, channel, and dist-tag from `scripts/release-channel.mjs`                                                                                                                                                                                                                                                                                                                                                                               |
| `scripts/generate-action-registry.mjs`         | regenerate CLI registry projections from policy                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |

Treat `package.json` as the canonical command catalog. Run a generator only when its owned
source changed, inspect the diff, and run its matching check mode where available. Generated
output is never hand-edited to make a gate pass.
